FUDO Products API (1.0.0)

Download OpenAPI specification:

Users, JWT authentication and asynchronous product creation.

RESTful API built on Rack (no web framework).

Conventions

  • JSON everywhere except GET /AUTHORS (plain text).
  • Errors always use the same shape: { "error": { "code": "...", "message": "..." } }. The code is stable and meant for programs; the message is for humans.
  • Strict request bodies: unknown fields are rejected with 400 invalid_body. 400 means the body is malformed or does not match the structure; 422 means the structure is right but a value breaks a rule (length, allowed characters).
  • Authentication: protected endpoints require Authorization: Bearer <access_token> (obtained from POST /auth/login). Tokens expire after expires_in seconds.
  • Ownership: a user only sees their own products and product requests. Resources of other users answer 404 (not 403), so their existence is not revealed.
  • Request id: every response carries X-Request-Id. Clients may send their own ([A-Za-z0-9_-], up to 64 characters); otherwise one is generated.
  • Compression: responses are gzip-compressed when the request sends Accept-Encoding: gzip.
  • HEAD is supported on every GET route. Unsupported methods answer 405 with an Allow header.
  • Rate limiting: any route may answer 429 with Retry-After. Limits per client IP: 300 requests/minute overall, 10 logins/minute, 10 registrations/hour; and 5 logins/minute per username.

Asynchronous product creation

  1. POST /products validates the name and answers 202 Accepted with a product request (status: pending), a Location header pointing to it and Retry-After: 5.
  2. About 5 seconds later a background worker creates the product.
  3. Poll GET /product_requests/{id} until status is completed (with product_id) or failed (with error, e.g. name_taken).
  4. The product is available at GET /products/{product_id} and in GET /products.

Products

Asynchronous creation and queries of the user's products.

Request the creation of a product (asynchronous)

Does not create the product: it records a product request and schedules its creation about 5 seconds later. Follow the Location header to check the result.

The name is trimmed. It must be unique per user, ignoring case and surrounding spaces: "Coca", "coca" and " coca " are the same name. A name already used by one of the user's products, or by one of their pending requests, answers 409 right away.

Product requests

Status of an asynchronous product creation.

Check the status of a product request

pending → completed (with product_id) or pending → failed (with error). Final states never change. While pending, the response includes Retry-After: 1.

Possible error values: name_taken (the name was taken meanwhile), enqueue_failed (the creation could not be scheduled), creation_failed (the creation kept failing after several retries).
